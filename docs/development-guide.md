# Development guide

This repository maintains the server from [bash-lsp/bash-language-server](https://github.com/bash-lsp/bash-language-server), synchronized with [upstream commit eee7729](https://github.com/bash-lsp/bash-language-server/commit/eee772929fb300e4798f3aa55428aafa66217a54). It contains one npm package and no bundled editor client. The Lumine adapter lives in the separate [ide-bash](https://github.com/lumine-code/ide-bash) repository.

## Prerequisites

Use Node.js 24 or newer and npm. Bash, ShellCheck, and shfmt are required for the full external-tool integration suite; Bash command documentation also uses the host's help and manual-page utilities. CI runs the portable suite on Windows, macOS, and Linux, and the complete suite on Linux with its external tools installed.

## Initial setup

Run these commands from the repository root:

```sh
npm ci --ignore-scripts
npm run build
node server/out/cli.js --help
```

`npm ci` installs the committed dependency graph. `npm run build` compiles the TypeScript server, emits declarations, and copies the command-option helper into `server/out`. There is no install-time compilation or client workspace to provision.

## Source layout

- `server/src/` contains the LSP server, analysis, completion, diagnostics, and tool integrations.
- `server/src/**/__tests__/` contains Vitest unit and integration tests.
- `testing/` provides fixtures and shared test helpers.
- `server/out/` contains the compiled package payload and is regenerated by the build.
- `server/tree-sitter-bash.wasm` is the parser shipped with the server; `server/parser.info` records its upstream source.
- `scripts/verify-package.js` checks the package payload.

Make server changes in `server/src`, then rebuild. Do not fix generated files or an installed consumer's `node_modules` copy directly.

## Validation

The npm scripts keep checks separate from commands that rewrite files:

```sh
npm run lint
npm run format:check
npm run typecheck
npm run test:portable
npm test
npm run test:coverage
npm run build
npm run verify:package
npm audit --omit=dev --audit-level=high
```

`npm run verify` runs lint, formatting checks, test type checking, the full suite, the build, and package verification. `npm run format` rewrites formatting. Tests run sequentially so subprocess and filesystem integration cases remain isolated. Coverage is written to `coverage/`.

`npm run test:portable` skips suites that require real shell documentation, ShellCheck, or shfmt processes. It still runs the portable server and lifecycle tests, including Windows compatibility checks. Run the full suite when the external tools are available and use its Linux CI job to verify those integrations.

Run a particular file or filter by test name with:

```sh
npm test -- server/src/__tests__/input-declarations.test.ts
npm test -- server/src/__tests__/server.test.ts -t rename
```

Tests and helpers are type checked using `tsconfig.test.json`. Test failures must be fixed in the implementation or test preconditions; do not remove a platform case to make CI pass.

## Compatibility scope

Keep the server behavior and tests aligned with upstream. The retained compatibility changes cover Windows PATH and PATHEXT executable discovery, extensionless executable aliases, native absolute sourced paths, invoking the command-option helper through Bash on Windows, and resolving CLI metadata from the single root manifest. Each difference needs a focused regression test so a later upstream synchronization can retain it or remove it when upstream provides the same behavior.

The fork uses a single root manifest, npm, current dependencies, and a Node.js 24 baseline. Its package layout remains `server/out` so existing consumers can resolve the compiled CLI. Upstream provenance and release history remain in `server/parser.info` and `server/CHANGELOG.md`.

## Run the server

The standalone CLI speaks LSP over standard input and output:

```sh
node server/out/cli.js start
```

Configure an LSP client to run Node with `server/out/cli.js` and `start` as its arguments. Set `BASH_IDE_LOG_LEVEL=debug` in the client's launch environment to inspect request handling through the client's server log. Server configuration is defined in `server/src/config.ts` and is supplied under the `bashIde` workspace configuration section.

## Test with Lumine

`ide-bash` is linked into the development editor, but its server dependency resolves from the adapter's own `node_modules`. Editing this sibling repository does not replace that installed dependency. Push a verified server commit, advance the adapter's immutable pin, and regenerate its lockfile with npm before validating the exact consumer payload.

Run `npm test` from the `ide-bash` checkout with `LUMINE_RESOURCE_PATH` pointing at the editor source. The adapter suite exercises resolution, settings, the full LSP feature surface, and the document lifecycle. Its deterministic ShellCheck and shfmt fixture processes run on Linux; Windows runs the same LSP requests with those optional tools disabled.

For a normal renderer session, follow the editor's [language-server testing guide](https://github.com/lumine-code/lumine/blob/master/docs/language-server-testing.md) and use `ide-bash/spec/drive.json`. Verify the window's console and DevTools issues as well as the protocol checks, and test the Electron runtime used by the editor.

## Update the parser

When synchronizing the server, take `server/tree-sitter-bash.wasm` and `server/parser.info` from the same upstream commit, then run parser, analysis, and full server tests. `lem` owns Tree-sitter tooling in the Lumine workspace; use `lem grammar` for grammar generation and builds. `scripts/upgrade-tree-sitter.sh` retains the upstream standalone update procedure and records the selected parser commit and ABI.
